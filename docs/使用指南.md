# 个人信息工作空间 v0.1

## 开始使用

Windows 便携包位于 `.build/release/workspace-windows-v0.1.0`。保留整个目录，双击 **工作空间.exe**，无需另装 Node 或包管理器。首次选择创建新工作空间，默认在本机建立；之后进入待办悬浮窗口。也可连接你已准备好的服务器。

输入文字，按 Enter 或“添加待办”保存；Shift+Enter 换行。看到本机保存成功后即可继续记录。点击任务查看详情，可修改文字、设置或清除截止日期、完成、恢复及明确删除。窗口标题栏可拖动；置顶可切换。正常退出重启后保留原空间和已保存进度。

“工作空间管理”中可查看当前空间身份、统一位置、同步状态、领域目录、MCP、导出恢复及迁移。程序文件与数据分开；更新程序时保留数据目录和原绑定。默认本机绑定位于系统应用数据目录的 `personal-information-workspace/workspace-initialization`，实际路径以界面及所选目录为准。

## 内置服务器连接与圆角悬浮窗

自 v1.2.0 起，在初始界面或“工作空间管理”的“服务器连接”中选择之前的 SSH 私钥，核对服务器、用户名、SSH 端口与主机 SHA256 指纹，勾选自动连接并保存。此后打开应用即可建立通道，短暂断网会自动重连，无需另开 PowerShell。原 PowerShell 通道若占用 43128 端口，先关闭原通道。已有空间仍沿用 `http://127.0.0.1:43128` 与原所有者凭据，不要重新创建空间。

私钥保存在本机用户数据目录并限制访问权限，不上传 GitHub 或服务器；首次配置及更换私钥应在断开后进行。需要 Windows OpenSSH 客户端，首版不在后台处理带口令私钥。通道状态与实际同步状态分别展示。

悬浮待办改为大圆角白色表面和淡外阴影，顶部空白可拖动，右侧提供最小化和关闭。关闭仍会保护未保存输入，原有置顶切换和管理入口保留。

## 应用更新

支持更新的首个版本为 v1.1.0。进入“工作空间管理”，在“应用更新”点击“检查更新”，查看当前版本、目标版本及新版说明，再点击“一键更新”。初次接入空间之前也能使用该入口。

下载期间继续保留旧程序；校验完成后按现有退出流程处理未保存输入，然后自动安装并重启。取消退出后可点击“安装并重启”。更新保留原空间绑定、本机数据和未同步内容，不会升级你的远端服务器或建立 SSH 通道。

网络失败、校验失败、目录不可写或公司策略限制时查看页面提示后重试。新版启动失败时尝试恢复旧程序；程序旁的 `.workspace-update-*` 目录保留旧包和结果材料。程序与数据目录重叠时拒绝自动替换，需先把整个应用移到独立目录。请勿将私钥或工作空间数据库放入应用程序目录。

v1.0.0 没有更新入口，需先完整解压新版到另一个目录并运行一次，已有绑定和本机数据仍沿用原路径。

## 多设备和自管服务器

### 拖动排序与多级子待办

- 拖动事项前的 **⠿** 到两条事项之间，调整同级优先顺序；越靠前越优先。拖到另一条事项中央，成为它的子待办。释放前可看到对应落点提示。
- 拖动父事项时，全部层级的子待办一起移动，内部结构保留；拖到“移到顶层”区域可以解除父级归属。使用箭头展开或折叠子事项。
- 子待办全部完成后，父事项才可手动完成。已完成子事项保留在未完成父事项下；根事项完成后整棵树进入已完成区，该区数量按顶层目标计。
- 将子事项恢复为未完成，或向已完成目标移入未完成事项时，受影响的已完成祖先一起恢复为未完成，并显示提示。
- 删除父事项会连同全部层级、已完成及折叠的后代一起删除。确认提示说明范围及数量；取消则全部保留。
- 跨设备发生整组冲突时，先阅读整组影响提示，再选择采用哪一方或恢复。正在编辑的子事项会保留整理材料，不能被另一端的子树删除直接抹去。

多设备使用此功能时，客户端和自管服务都使用本次新版；旧服务在能力检查阶段停止整体操作，旧客户端不会取得不完整的树形进度。更新程序时继续保留原数据目录与绑定。

### 连接统一位置

Ubuntu 使用 `.build/release/workspace-server-ubuntu-v0.1.0.tar.gz`，按 [Ubuntu服务器部署](Ubuntu服务器部署.md) 解压并执行安装器，提供固定凭据、持久数据和 systemd 托管；Windows 独立服务目录为 `.build/release/workspace-server-windows-v0.1.0`。兼容的通用服务器包仍位于 `.build/release/workspace-server-v0.1.0`，使用 Node.js 22.23.0 或已验收的兼容运行时启动；无需 Electron。Windows 便携包也可使用“启动服务.cmd”。在启动终端设置：

```powershell
$env:WORKSPACE_DATA_DIRECTORY = 'D:\PersonalWorkspace'
$env:WORKSPACE_BOOTSTRAP_TOKEN = node -p "require('node:crypto').randomBytes(32).toString('hex')"
$env:WORKSPACE_PORT = '43127'
node apps/server/dist/composition/main.js
```

凭据首次生成后安全保存，重启沿用，不能每次更换。便携包无独立 Node 时可由自己的秘密管理方式设置至少 32 字符凭据，再运行服务启动文件。服务默认只监听本机回环地址。公网使用由你管理的 HTTPS 反向代理，客户端拒绝公网明文 HTTP。数据目录使用持久磁盘并保持单实例；程序不会购买或部署云资源。

在其他客户端选择“连接已有工作空间”，填写当前服务地址和所有者凭据，核验两项身份后确认接入。同一设备保留本机原操作，不重新创建空间。已保存内容可离线使用；网络恢复后补同步。正常在线回环环境已验证另一桌面实例在 30 秒内取得确认更新；挂起、公网和移动端不在该实测范围。

## 领域与冲突

内置待办随客户端提供。添加独立扩展使用随包“扩展样例”中的 JSON，先查看声明再登记、启用。停用或移除本机程序不删除领域数据；其他设备不自动安装程序。缺失或不兼容程序时显示待补齐，使用原兼容包补齐后再进入。服务器自定义程序需通过具备对应管理权限的 MCP 安装动作补齐，不凭恢复文件自动执行。

同一属性并发修改、删除与编辑相遇时保留冲突材料。进入冲突处理，可保存整理内容并明确选择；提交后仍等统一位置确认。未知结果沿原操作核对，不用重复新增或删除来猜测结果。

## 导出和恢复

1. 在管理页选择统一位置或本机来源，查看领域、未同步和冲突范围，确认后保存文件。统一位置包不包括其他设备未上传成果；本机包仅包含本机持有进度，离线也能导出。普通未提交输入需先保存。
2. 保存对话框可选择路径；已有文件替换需要明确选择。只有文件写入、刷新并重读校验通过才显示完成。导出时点之后的改动留在原空间，可再次导出。
3. 选择“恢复工作空间数据”，选材料和空白目录，核对身份、来源、时点、领域及待处理摘要后确认。非空目标、损坏材料、核心不兼容均停止。预览和取消不改变目标与绑定。
4. 本机包恢复后可在未绑定的客户端点击“使用恢复的本机进度”，可用领域可以离线工作。已有绑定的客户端保留原副本，不自动替换；联网前核验原空间当前生效位置。旧地址仅作来源说明。
5. 统一位置包恢复后是待启用目标，不自动接受写入；按下节迁移流程切换。缺失扩展的数据和冲突材料仍保留且可再次导出；访问秘密不在文件内，需要重新授权。

服务端可先在服务器独立包目录预览和恢复：

```powershell
node scripts/archive-cli.mjs preview D:\snapshot.workspace.json D:\RestoredWorkspace
node scripts/archive-cli.mjs restore D:\snapshot.workspace.json D:\RestoredWorkspace
```

Windows 便携包可用“恢复数据.cmd”传入相同参数。中断后使用同一材料与原目标重试，先核对已有完成回执；未完成文件不会被发布成可用空间。

## 迁移统一位置

1. 旧位置可达时点击“停止旧位置写入以开始迁移”，确认已停写，再从统一位置导出。设备仍可按离线规则保存，待以后补同步。
2. 用该包恢复到空白目标。远端需在新服务器执行恢复，并以新的所有者凭据启动服务；目标暂不接受写入。
3. 在“迁移统一位置”填写已恢复本机目录或新服务器地址及新凭据，点击明确切换。客户端会核对同一空间身份和目标状态；成功后使用原副本补同步，旧位置保持停写。
4. 旧位置不可达时，必须由你先停用或隔离它，并勾选相应确认。网络超时本身不能证明它已停用。选用本机包替代时同时接受其覆盖边界，不能恢复其他设备未知成果。
5. 本机包替代统一位置时，先在当前客户端完成该包恢复，再在迁移目标选择该恢复目录；程序在其 `authority` 子目录准备统一位置，原 `replica.sqlite` 保留待同步及冲突。独立服务器使用 `prepare-local-authority` 命令准备目标，原本机恢复副本仍须接入以提交未同步操作。
6. 其他设备各自重新核验并接入相同空间的新位置；不要新建空间代替接入。切换失败保留旧绑定、待同步材料和目标，可核对后重试；不会自动重新开启旧位置。

## 外部 MCP 客户端

管理页创建具名授权，选择领域和必要动作；默认只读。保存首次显示的 credential，之后可以隐藏或撤销。使用独立 Node 运行 `apps/mcp/protocol/main.mjs`，设置 `WORKSPACE_MCP_URL` 为当前服务地址、`WORKSPACE_MCP_TOKEN` 为具名凭据。Windows 便携包可使用其 `resources/app/apps/mcp/protocol/main.mjs`。所有者凭据不能交给外部 Agent。

通用 stdio 客户端配置：

```json
{
  "mcpServers": {
    "workspace": {
      "command": "node",
      "args": ["你的程序目录/apps/mcp/protocol/main.mjs"],
      "env": {
        "WORKSPACE_MCP_URL": "http://127.0.0.1:43127",
        "WORKSPACE_MCP_TOKEN": "具名接入凭据"
      }
    }
  }
}
```

Codex 和 Claude Code 按各自客户端当前配置入口填写 stdio 命令、参数及上述环境变量；本轮实际端到端验证的是独立官方 SDK 客户端进程，不宣称已运行这两个具名客户端。删除需逐次具体对象确认；不支持客户端确认交互时由所有者页面承接。

## 验证范围

Windows 真实 Electron 窗口、Node 与 Electron 内置 SQLite、独立 HTTP 服务、双桌面同步、SDK stdio MCP、自定义扩展及导出恢复迁移都有自动验收。Ubuntu 22.04 x86_64 的 WSL 环境已使用独立 Linux Node 22.23.4 验证服务和数据接续，systemd unit 通过静态验证；阿里云主机开机托管、公网 TLS、arm64、macOS、Android 及具名第三方 Agent 客户端未宣称已实测。
