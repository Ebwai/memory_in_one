# 一致快照生成 [M]

状态：产品规则已确认；2026-10-26 已完成 N51：事务一致快照与原身份、删除、未同步及冲突接续材料校验。

## 功能描述

将已经明确范围的数据在一个一致时点形成可恢复材料，避免导出过程中读取到互相矛盾的内容与进度。

## 定位

```text
工作空间数据导出
└── 一致快照生成 [M] ●
```

## 业务规则与约束

- [已确认] 一次导出确定明确的一致时点，领域登记、内容、状态及其必要接续材料相互匹配；不能混入前后不一致的半份更新。
- [已确认] 一致时点之后用户继续保存的改动仍留在原空间，但不悄悄加入本次导出；用户可再次导出取得之后的进度。
- [已确认] 记录空间身份、来源、导出时点、领域及兼容性说明，使后续能确认材料范围，不依赖原服务器地址才可读取。
- [已确认] 包含范围内的未同步操作、删除进度和冲突材料时，保持它们与原内容的关系；不能只保留显示文字而丢失继续处理依据。
- [已确认] 数据缺失、读取失败或关系无法保持时不作为完整快照交付，不修改或清空原空间。具体格式与校验方法不在 PRD 指定。

## 交互流程和细节

范围确认 → 在所选来源取得一致时点的数据 → 汇集恢复必要信息 → 生成可交付材料；失败反馈具体可处理原因。正常导出不要求用户逐条锁定任务，迁移导出仍先遵循旧位置停止写入规则。

## 数据范围

仅包含同级导出范围确认已确定且来源持有的数据，既不复制为新的工作空间身份，也不虚构未取得内容。

## 前置能力

引用同级 [导出范围确认](../导出范围确认/导出范围确认.md)，复用既有可靠保存、领域数据和同步结果含义。快照自身不依赖恢复已执行。

## 边界情况与异常处理

[已确认] 导出中修改、删除、接收同步更新，不产生半旧半新的材料；操作中断不影响原内容。来源出现无法识别的数据时保留原始材料或明确无法完整生成，不能静默丢弃后称完整成功。

## 验收标准

并发编辑、完成或删除期间导出的内容仍对应一致时点；后续更新保留在原空间；未同步和冲突材料与原内容可对应；缺失数据不伪报完整快照。
