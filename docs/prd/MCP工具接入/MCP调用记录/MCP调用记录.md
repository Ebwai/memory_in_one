# MCP调用记录 [C]

状态：产品规则已确认；2026-10-26 已完成 N44 实现及后续 MCP 链路验收。导出恢复留存约束仍须在后续数据携带节点验证。

## 功能描述

让用户查看外部 MCP 客户端或 Agent 对领域发起的写操作及接入授权变更，判断哪个调用来源对什么对象执行了什么动作、结果如何。这里记录工具执行，不开发或保存本软件内的 Agent 推理过程。

## 定位

```text
MCP工具接入
└── MCP调用记录 [C] ●
```

## 业务规则与约束

- [已确认] 记录接入来源、所属空间与领域、工具动作及对象、时间、必要摘要、是否经过用户确认及明确结果；领域内容写入、领域管理写操作、授权创建和撤销同样留有记录。
- [已确认] 成功、失败、等待用户确认、结果不明和冲突可区分；同次动作重试接续同一结果，不伪造多次成功操作。
- [已确认] 内容写入的已确认结果与来源记录可靠关联，不出现已向 Agent 报告成功、却找不到该操作来源的情况。具体一致性实现留给技术设计。
- [已确认] 用户可从 MCP 接入管理查看记录，外部客户端也可在授权范围查询调用状态与结果，不必切回业务窗口判断操作是否成功；目标已删除时仍保留必要对象说明。
- [已确认] 记录是工作空间数据，随导出恢复保留；不将访问凭据或模型内部推理写入普通记录，也不要求保存与结果无关的完整对话。
- [已确认] 撤销授权不删除其历史操作记录，也不自动撤销此前已确认改动；本节点不新增自动回滚或完整内容版本历史功能。

## 交互流程和细节

接入授权变化或 MCP 写工具形成结果 → 可靠留下关联记录 → 用户从管理界面或外部客户端查看结果 → 需要处理时进入已有内容或冲突路径。记录本身不直接再次执行原动作。

## 数据范围

授权变更与 Agent 写操作的来源和结果，不在本轮强制记录每次只读查询的完整内容。

## 前置能力

需要工作空间身份、可靠保存及动作结果含义；记录留存是授权变化和写入的支撑，不反向要求 Agent 已成功写入才可建立记录能力。

## 边界情况与异常处理

[已确认] 结果不明先保留可核对状态，再沿原动作接续，不因日志显示失败而重复执行。恢复材料中的旧记录不自动重新执行，也不自动重新授予已撤销或历史授权。

## 验收标准

可识别 Agent 来源、动作、对象和结果；重试不伪造重复成功；删除后仍可追溯；授权变更可查看；导出恢复保留记录但不执行历史动作或恢复旧凭据效力。
