# MCP领域管理工具 [C]

状态：产品规则已确认；2026-10-26 已完成 N48 领域目录、注册、启停及服务器声明式程序管理。当前通道只管理服务器；其他客户端程序目标明确不可用。

## 功能描述

将已有领域管理动作暴露为外部 Agent 可发现和调用的 MCP 工具，让用户可通过外部客户端管理领域，不只查询领域内容。

## 定位

```text
MCP工具接入
└── MCP领域管理工具 [C] ●
```

## 业务规则与约束

- [已确认] 提供领域目录、可用性、启用状态和业务能力的查询工具，包括已停用或缺失程序的登记信息，不把这些领域伪装成不存在。
- [已确认] 在独立授权下提供已有领域扩展注册、兼容程序补齐、启用、停用和本机自定义程序移除动作，复用四项已确认管理规则，不另外发明 Agent 专用生命周期。
- [已确认] 启用状态影响工作空间，程序安装与移除仅影响实际执行接入端的本机，工具描述与结果明确作用范围。服务器不凭这一授权操控任意其他客户端的程序目录；目标能力不可用时明确返回不可用。
- [已确认] 停用或移除仍保留数据及未同步成果；未保存输入等需要用户选择的场景，返回待确认信息并由外部客户端承接，不静默丢弃。
- [已确认] 新领域登记并具备兼容处理后，其声明的业务工具可由统一 MCP 入口发现；停用或缺失程序时，外部 Agent 能得知对应能力不可用。无需为每个领域创建独立权威数据源或要求用户额外操作另一套 MCP 服务。
- [已确认] 内容写权限不等于领域管理权限；迁移服务器、恢复数据等工作空间管理权限也不因领域管理授权自动开放。工具不根据自然语言正文自行扩大范围。

## 交互流程和细节

用户通过外部客户端发出领域管理指令 → Agent 发现并选择相应管理工具 → 本服务核对授权、当前状态和实际执行位置 → 复用既有领域管理能力 → 返回结果与调用记录，由外部 Agent 反馈。

## 数据范围

领域登记、可用程序信息、启用状态及管理动作结果；具体内容业务工具由各领域声明，todo-list 仍保有其专属定义。

## 前置能力

引用同级 MCP接入授权及 MCP调用记录；复用 [信息领域管理](../../信息领域管理/信息领域管理.md)中的目录、注册、启用状态及程序移除四项能力。业务工具发现随领域能力变化，不以 Agent 已执行过业务动作作为管理工具可用的前提。

## 边界情况与异常处理

[已确认] 无兼容程序、无相应执行位置、权限不足、离线状态尚未确认或并发启停时明确返回结果，遵循既有保存和冲突机制；需要用户确认的动作不能因 MCP 调用而跳过，也不能要求模拟点击某个固定窗口才能完成。

## 验收方向

从外部 MCP 客户端可查询全部已授权领域状态，并按管理权限启停或执行可用的注册和程序管理动作；状态与人工界面一致；停用和移除不删数据；新领域工具可发现；所有结果能回到外部客户端。
