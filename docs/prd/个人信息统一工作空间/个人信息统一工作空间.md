# 个人信息统一工作空间 [C]

状态：整体产品方向及子能力规则已逐轮确认；首版范围、里程碑与整体验收仍为候选，未因本轮文档结构调整而自动确认。2026-10-26 已实现至 N62，具体交付与实测范围见 [交付验收](../../交付验收.md)，不改变候选规格的确认状态。

## 功能描述

将不同设备记录的信息与后续进度归入同一个人工作空间，按信息领域组织，支持数据自主迁移，并通过 MCP 供外部 Agent 调用已有领域能力。

## 业务规则与约束

- 同一工作空间的信息及进度围绕同一权威来源持续推进；设备本机副本和待同步成果仍属于原空间。
- todo-list 是首个具体领域。创建空间时默认加入内置待办，之后添加的领域各自定义内容类型、数据和界面。
- 用户掌握存放环境及可携带数据，支持从导出材料恢复和迁移；具体数据覆盖及恢复边界以数据自主与迁移子树为准。
- 外部 Agent 负责理解文字或语音指令及工具编排，本软件通过 MCP 工具复用领域能力和同一份数据。
- 具体任务规则、领域生命周期、保存同步与 MCP 授权规则只在各自节点维护；本节点只保留整体范围和产品级验收。

## 交互流程和细节

创建或接入空间 → 使用对应领域快速记录 → 回看并继续推进 → 通过已有同步机制在其他设备接续；外部 Agent 可在授权后通过 MCP 操作同一领域。需要携带数据时使用导出、恢复及明确的迁移切换路径。

## 数据范围

当前空间的领域登记、领域内容及进度、保存与同步接续材料、冲突材料、MCP 授权定义及调用记录。每类数据的准确范围以所属节点定义，不因本文件概括而新增字段或无限历史能力。

## 前置能力

由上述四个功能包组合成立。底层共享机制由公共机制区提供；具体实现顺序见 [顶层 PRD 的节点队列](../../PRD.md)，不能反向要求工作空间总验收先通过，才可实现其组成能力。

## 边界情况与异常处理

单个领域不可用、保存或连接失败、冲突、缺失程序及迁移中断等行为遵循对应子节点规则。错误不能伪装为空数据或完整成功。整体验收须覆盖这些边界，不能只验收可见界面。

## 首版交付范围（PRD Baseline 候选）

本节为本轮整体确认项。首版 v0.1 是以下能力全部完成并通过验收后的完整交付；分阶段的可运行成果不代替最终交付，也不把已纳入首版的能力自动推迟到后续版本。

### 首版纳入

| 范围 | v0.1 交付行为 |
|---|---|
| Windows 客户端 | 可运行客户端；默认可直接进入内置 todo-list 悬浮界面，可进入工作空间与领域管理；可拖动、置顶切换、快速记录及详情编辑 |
| 个人统一工作空间 | 面向个人及其多设备；可在本机创建，也可创建或接入自管服务器上的同一空间，交付服务端及启动、连接说明；同一空间只有一个生效统一位置 |
| todo-list | 现有 11 个待办原子能力与全部已确认规则，包括可选截止日期、持续显示、完成与恢复、删除及冲突适配 |
| 可靠保存、同步与离线 | 本机保存即继续、重启接续、双客户端同步、删除传播、离线领域操作、补同步、冲突保留与选择；正常条件下 30 秒同步获取目标 |
| 领域管理与扩展 | 统一目录、内置及用户自定义扩展注册、启停、本机自定义程序移除、缺失程序的数据保留与补齐；提供最小扩展样例和接入说明，具体程序载体与接口由架构和 TDD 定义 |
| 数据导出、恢复与迁移 | 统一位置与本机两类导出、完整文件与一致快照、空白目标恢复、未同步与冲突材料接续、缺失领域数据保留，以及明确的唯一统一位置迁移切换 |
| MCP 服务 | 供外部 Agent 发现并调用领域管理、内容查询和写操作工具；可撤销授权、对象确认、真实结果与调用记录；与人工界面共用领域规则及数据 |

### 交付边界

- 首版原生客户端优先 Windows。macOS 与 Android 原生客户端保留在产品方向中，安排后续版本；本轮不把未实际开发的平台声称为已支持。
- 首版正式内置信息领域为 todo-list。项目想法、读书笔记等仅是以后可接入的独立领域示例，不在首版额外开发完整业务；自定义扩展机制及最小验证样例仍属于首版。
- 语音输入、自然语言理解与 Agent 编排由外部客户端承担，本软件交付 MCP 服务与工具；不把自建 Agent、语音识别引擎或模型供应商接入加入本轮软件职责。
- 首版面向同一用户的个人空间与多设备，不扩展为团队成员、组织角色或多人协作产品；外部 Agent 的范围授权照常保留。
- 全局快捷键、开机自启、系统托盘、任务提醒、周期重复、日历视图与任意多工作空间合并均不作为本轮新增必交付项；已保存内容在退出并重新启动后须能找回。未来引入这些能力时再新增或更新对应产品节点。
- 服务端运行环境、客户端封装、MCP 传输和客户端兼容版本在架构基线中具体化；本 PRD 不提前编造选定 SDK、数据库或部署完成的事实。

## 首版整体验收

1. Windows 客户端启动后可直接快速记录；新增、编辑、可选日期、完成与恢复、删除、详情及每日显示均符合 todo-list 规则。
2. 本机可靠保存成功后可继续记录；退出重启不丢已保存内容、待同步操作和冲突整理材料；失败与结果不明的反馈真实可核对。
3. 至少两个独立 Windows 客户端实例接入同一统一位置，验证新增、更新、删除、离线重连、重复请求和并发冲突；正常联通条件下，另一在线实例在统一位置确认后 30 秒内取得更新。可用隔离客户端实例模拟双设备，但不能将它表述为已测试未实际运行的原生平台。
4. 在本机环境与自管服务器环境分别验证创建／接入与数据持续性；交付可运行的服务端及启动、连接指南，不要求购买特定供应商资源。
5. 通过真实外部 MCP 客户端完成工具发现、任务查询及写操作，验证领域启停、授权撤销、对象确认和结果返回。提供 Codex、Claude Code 接入配置说明；分别记录实际验证的客户端及版本，未实际运行的客户端不声称已兼容。至少一个真实客户端的端到端调用通过后才完成本轮 MCP 演示验收；MCP 协议级测试覆盖其余工具契约。
6. 用一个独立于 todo-list 数据模型的最小验证扩展，验证注册、数据归属、启停、程序缺失／补齐和工具发现；这是扩展机制的开发样例，不增加新的正式产品领域。
7. 导出包含停用领域、未同步进度、冲突材料与调用记录的所选来源数据，在空白目标恢复；核对身份及进度。损坏包、非空目标、缺失领域程序和中断重试按既定规则处理。
8. 执行统一位置迁移，确认旧位置不再接受写入，目标恢复后明确切换；原客户端携未同步成果接入同一空间的新位置，不静默覆盖、复活旧内容或同时写向两处。
9. 交付 Windows 可运行客户端、服务端、MCP 接入说明、自定义扩展最小样例、导出恢复及迁移指南。所有“通过”由实际检查记录支持；仅有需求和架构文档不算软件交付。

## 验收衔接

- 早期本机待办完成局部验收后，仍需参加同步、领域生命周期、MCP 和导出恢复接入后的集成验收。
- 创建、接入先于正式迁移切换；恢复完成不自动启用第二个可写统一位置。
- 外部工具与人工界面沿用同一业务能力，不为 Agent 建立独立进度副本。
- 实际验收结果写入后续实施与测试记录；本候选文档不声称软件已经运行或测试通过。
