# 桌面应用更新

## 功能描述与定位

用户在应用内检查公开仓库的新版本并一键下载、安装和重启。

```text
桌面应用更新 [C]
├── [[正式版本发现/正式版本发现.md|正式版本发现]] [M] ●
└── [[更新安装与接续/更新安装与接续.md|更新安装与接续]] [C] ●
```

## 业务规则与约束

只向固定的 Ebwai/memory_in_one GitHub Release 检查正式版本；只有比当前版本高且适配当前 Windows 架构的完整应用包才可更新。草稿、预发布、旧版本及缺失校验信息的附件不作为可安装版本。

检查和下载由用户主动发起，展示当前版本、目标版本、发布说明、下载进度和失败原因。下载及校验完成前保留运行中的旧程序；不把网络失败显示为“已是最新版”。重复点击不并行安装。

安装仅替换程序，不迁移或删除本机数据、绑定、凭据和未同步成果，也不升级远端服务器。复用既有领域退出草稿保护：有未保存输入时可保存、放弃或取消；提交中或结果未确认时先核对。取消退出后保留已下载版本，之后仍可安装。

## 交互流程

1. 在初始界面或“工作空间管理”打开“应用更新”，点击“检查更新”。
2. 有新版时展示版本与说明；点击“一键更新”，下载并校验应用包。
3. 自动进入退出处理；无未保存输入时直接安装重启，否则先处理输入。也可稍后点击“安装并重启”。
4. 新程序沿用原空间；安装或新程序启动失败时恢复旧程序，保留明确结果和旧包备份。

## 边界与异常

无网络、限流、下载中断、校验失败、空间不足、目录无写权限或文件占用时保留旧程序并允许重试。源码运行时可检查但不执行替换；公司管理策略阻止执行时说明失败，不绕过策略。旧版没有该入口时需先手动安装首个支持更新的版本。

## 前置能力与数据范围

复用领域生命周期的草稿退出处理和程序/持久数据分离；仅下载程序资源，不向 GitHub 发送工作空间数据或所有者凭据。
