# 信息领域管理 [C]

状态：产品规则已确认；2026-10-26 已完成 N61：领域生命周期及独立扩展的恢复、再导出和补齐整合。

## 功能描述

让不同类型的信息在统一工作空间中拥有适合其用途的组织方式，并允许用户扩展新的类型。

## 业务规则与约束

来自用户的已知要求：待办、项目想法等不同类型内容需要被归纳管理；统一界面应清晰呈现已经加入的类型；未来支持用户自定义扩展。首个信息领域为待办。

已确认暂用“信息领域”描述面向用户的内容分类；用户自定义扩展的注册与运行规则已确认，扩展程序格式和接口留给技术设计。

已确认的结构调整：todo-list 是本工作空间的首个具体信息领域，所有待办专属概念和机制在其子树定义。信息领域管理仍负责领域发现、注册与管理等跨领域职责，不在本节点混写待办的日期或完成规则。todo-list 是具体领域组成，本节点四项管理动作不复制其业务规则。

术语边界（用户于 2026-10-25 再次确认）：创建“工作空间”是建立整体信息容器；注册“领域扩展”是在已有空间中加入一种内容能力。默认启用内置 todo-list 只发生在创建整体工作空间时。以后新增的项目想法、读书笔记等扩展各有自己的内容类型、数据和界面，不默认包含 todo-list；这些名称仅作说明，不表示本轮新增对应领域需求。

[已确认] 统一目录展示已登记领域的启用状态及本机程序可用性；可从目录进入已启用且可用的领域。注册核对稳定身份与兼容性，不重复建领域、不覆盖旧数据。停用或移除程序不等于删除数据。

[已确认] 领域登记与启用状态在工作空间共享，程序是否安装和可运行属于每台设备的本地状态。其他设备不自动安装用户代码，缺失程序时保留数据和待补齐状态。

## 交互流程和细节

用户查看目录 → 进入可用领域；或添加扩展 → 校验并登记 → 明确启用。用户可停用领域或移除本机自定义程序，数据与待同步进度保留，后续可补齐程序再使用。详细流程见四个直接管理节点，均已确认。

## 数据范围

已加入的信息领域及其内容归属；具体数据字段不在本层确定。

## 前置能力

登记与状态保存使用工作空间已有保存和同步规则；领域数据导出与恢复复用既有能力；目录依赖登记及状态，但登记入口不依赖进入业务领域。本节点不重复定义记录与推进行为。

## 边界情况与异常处理

[已确认] 缺失或不兼容程序时领域仍出现在目录中，但不能进行无法验证的业务写入；数据和恢复材料仍可导出。注册、启停失败不虚报成功，停用前未保存输入需先保存或明确放弃，不静默丢失。详见子节点。
