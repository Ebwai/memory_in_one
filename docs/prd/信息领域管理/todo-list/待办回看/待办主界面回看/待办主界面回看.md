# 待办主界面回看 [C]

状态：原子节点及以下具体规则已于 2026-10-25 经用户确认。

实现状态（2026-10-25）：N18 已实现稳定排序、默认折叠的已完成区及数量、长文详情与全量滚动访问；真实空列表、加载中和读取失败分别呈现。完成入口当前只读展示，实际切换由后续推进节点接入。

## 功能描述

在 Windows 悬浮主界面查看已有待办与当前状态，直接选择下一件要处理的任务。

## 定位

```text
待办回看
└── 待办主界面回看 [C] ●
```

## 业务规则与约束

2026-10-26 层级扩展：手动排列优先于默认创建时间排序，同级之间独立排序；未完成父事项下保留已完成子事项，根事项完成后整棵树进入已完成区；数量按已完成顶层目标计。默认创建时间规则适用于尚未手动排列的同级事项。见 [待办层级回看](../../悬浮待办拖动组织/待办目标层级组织/待办层级回看/待办层级回看.md)。

- 用户已要求：新任务默认进入主界面，任务前有完成勾选入口。
- [已确认] 主区呈现显示判定所确定的未完成任务，每条展示任务内容、未勾选状态和可选的截止日期标签。
- [已确认] 未完成区按创建时间从新到旧排列；相同创建时间保持稳定顺序。新增任务在顶部出现，日期标签变化不导致列表自动重排。
- [已确认] 已完成区默认折叠，展示数量，展开后按完成时间从新到旧查看；本轮不增加自动删除历史的规则。
- [已确认] 长内容可在列表中截断，并可通过详情查看完整内容；任务多时可滚动浏览，不静默遗漏任务。

## 交互流程和细节

前置条件：客户端可用，已取得可展示的任务信息。

1. 用户打开悬浮主界面，默认看到未完成区。
2. 点击任务文字进入详情查看；点击前面的勾选入口由待办推进处理完成操作，两者不混同。
3. 用户可展开或折叠已完成区，点击其中任务查看详情。

## 数据范围

当前待办领域的已有任务、状态及截止日期；本节点不新建、修改或完成任务。

## 边界情况与异常处理

[已确认] 没有未完成任务时显示“暂无未完成任务”，已有完成任务仍可展开。任务总数为零时提示可添加第一条任务。加载未结束或获取失败不显示为真实空列表；有可确认已保存的内容时保留展示并说明最新状态未确认，避免覆盖用户已有认知。

## 验收标准

新任务在未完成区顶部出现；长任务可查看全文；多条任务可滚动访问；已完成任务默认折叠且可找回；真实空列表、加载中和获取失败可区分。
