# 待办显示判定 [M]

状态：原子节点及以下具体规则已于 2026-10-25 经用户确认。

实现状态（2026-10-25）：N16 已实现本地日历日判定、五类显示规则、跨日及恢复刷新、非法日期和未知状态反馈；投影不修改任务或生成每日副本。

## 功能描述

确定待办是否进入主界面的未完成区或已完成区，并根据截止日期给出明确的时间状态，不创建每日副本。

## 定位

```text
待办回看
└── 待办显示判定 [M] ●
```

## 业务规则与约束

[已确认] 首个待办版本采用以下规则，表中均以任务仍存在为前提：

| 任务状态 | 截止日期 | 呈现位置 | 日期标签 |
|---|---|---|---|
| 未完成 | 未填写 | 主界面未完成区，每天持续显示 | 不显示日期标签 |
| 未完成 | 晚于今天 | 主界面未完成区，每天持续显示 | 截止日期 |
| 未完成 | 等于今天 | 主界面未完成区 | 今天到期 |
| 未完成 | 早于今天 | 主界面未完成区，直到完成或删除 | 已逾期及截止日期 |
| 已完成 | 任意或未填写 | 已完成区，默认折叠 | 保留已填日期，不再强调逾期 |

- 用户已要求：未填写属性的任务每天出现；这一规则不生成每天各一条的新任务。
- [已确认] 仅设置截止日期不隐藏任务；未到期任务不自动等待到截止当天才出现，逾期也不自动消失。
- [已确认] 截止日期仅到日，不包含具体时刻；“今天”取当前设备本地日历日期，截止当天整天算今天到期，下一天才算逾期。
- [已确认] 设备跨日、恢复使用或本地日期变化后重新判定，窗口保持打开也应反映日期变化。
- [已确认] 已完成状态优先于日期标签判定。撤回完成后，按任务原有日期和当前日期重新进入未完成区；操作能否撤回及其流程由待办推进确认。
- [待后续明确] 如果以后增加计划开始日期、项目归属等属性，逐项规定是否影响主界面；本轮不把“任意属性非空”视为隐藏依据。

## 交互流程和细节

本机制不提供独立操作入口。列表出现、任务状态或日期变动后，用户看到对应区域与日期标签变化；是否可编辑日期由待办推进规定。

## 数据范围

任务是否存在、完成状态、可选截止日期和当前设备本地日期。不同设备时区不同可能造成日期标签暂时不同，但不改变共享的任务内容和截止日期本身。

## 边界情况与异常处理

[已确认] 无截止日期不等于逾期；只按明确填写的日期判定。信息无法读取或日期值不可识别时，不静默隐藏任务、不伪造截止日期，向用户说明无法判定；无有效状态的内容不伪装成已完成。

## 验收标准

无日期、未来日期、今天、过去日期和已完成五类情况符合表格；跨日只更新标签，不增加任务；完成项不再计为未完成逾期任务。
