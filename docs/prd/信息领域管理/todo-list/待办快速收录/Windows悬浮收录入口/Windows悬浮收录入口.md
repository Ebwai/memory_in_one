# Windows悬浮收录入口 [C]

状态：原子节点及以下具体规则已于 2026-10-24 经用户确认。

实现状态（2026-10-25）：N12 已实现已绑定且启用待办时启动直接录入、默认置顶、置顶切换及系统标题栏拖动，窗口操作保留草稿；可返回空间管理。

## 功能描述

在 Windows 日常使用场景中提供可直接开始记录的悬浮主界面。

## 定位

```text
待办快速收录
└── Windows悬浮收录入口 [C] ●
```

## 业务规则与约束

- 用户已明确：Windows 客户端支持悬浮主界面，能够快速新增待办。
- [已确认] 客户端启动后直接显示悬浮主界面和任务输入区域，新增任务无需先打开独立表单。
- [已确认] 窗口默认置顶，可拖动位置，并允许用户切换置顶状态。置顶以普通桌面窗口场景为验收范围。
- [基线范围提案] 首版通过启动客户端直接进入已启用的待办悬浮界面，也可返回工作空间管理；退出客户端后再次启动可找回已保存内容。托盘、全局快捷键、开机自启及窗口位置记忆不作为本轮新增必交付项，关闭与最小化的具体窗口交互在后续界面设计中围绕上述入口落实。

## 交互流程和细节

前置条件：客户端已正常启动。

1. 用户看到悬浮主界面及任务输入区域。
2. 可移动窗口以避开工作区域，或切换置顶状态。
3. 点击输入区域后直接开始记录，由“待办内容录入”承接。

用户可观察结果：新增入口常驻在主界面，普通桌面应用之间切换时可按当前置顶选择保持可见。

## 数据范围

本节点不创建任务；只提供收录入口及当前窗口的展示状态。

## 前置能力

无已定义产品前置依赖；与同级“待办内容录入”衔接。

## 边界情况与异常处理

[已确认] 拖动窗口或切换置顶不提交、不清空正在输入的文字。系统安全界面和独占全屏场景不承诺强制覆盖。

## 验收标准

启动即可看到输入区域；可拖动窗口；默认在普通窗口上方显示，取消置顶后可正常被其他窗口遮挡；这些窗口操作不丢失未提交内容。
