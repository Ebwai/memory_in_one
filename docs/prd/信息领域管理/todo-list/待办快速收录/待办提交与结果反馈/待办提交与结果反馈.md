# 待办提交与结果反馈 [C]

状态：原子节点及以下具体规则已于 2026-10-24 经用户确认。

实现状态（2026-10-25）：N13 已实现按钮与 Enter、IME 选词防误提交、提交期间只读与同操作去重、本机确认后清空和焦点保持、失败保留及原操作核对。反馈不宣称已联网同步。

## 功能描述

将用户已录入的文字提交为一条待办，明确反馈结果，并让用户能够继续快速记录或在失败后重试。

## 定位

```text
待办快速收录
└── 待办提交与结果反馈 [C] ●
```

## 业务规则与约束

- [已确认] 点击添加按钮或按 Enter 提交；中文输入法正在选词时的 Enter 仅完成选词。
- [已确认] 新任务初始为未完成，可选属性为空。成功创建后默认出现在悬浮主界面，不要求先分类或打开详情。
- [已确认] 一次提交尚未结束时，连续点击或按键不重复创建同一条任务。
- [已确认] 提交成功后清空已提交文字，输入区域保留焦点，便于连续记录；失败时保留文字并允许编辑、重试。
- [已确认] 提交期间保留当前文字并暂不接受新的编辑，避免提交完成后误清除用户新输入的内容。
- [已确认] 不按文字内容自动去重，允许用户在一次提交结束后主动创建相同文字的新任务。
- [已确认] 本机可靠保存成功即可清空已提交输入并继续记录，不必等待网络同步；本机失败保留输入，结果不明沿原操作核对。离线受理与状态遵循统一进度保障的已确认规则，创建反馈不能被表述为所有设备已经同步。

## 交互流程和细节

前置条件：录入内容有效，当前没有尚未结束的提交。

1. 用户通过按钮或 Enter 提交。
2. 系统显示提交中的反馈，并避免同一次提交被重复触发。
3. 成功：主界面出现一条未完成任务，已提交文字清空，用户可继续输入。
4. 失败或结果无法确认：保留原文，明确说明未能确认保存结果；结果明确失败时允许重试。结果不明时重试也不得产生同一次提交的重复任务，具体保障由“统一进度保障”承接。

## 数据范围

当前提交的待办内容、创建结果及用户可见状态。完成后显示、排序和其他日期条件由“待办回看”定义。

## 边界情况与异常处理

失败时不显示虚假的成功、不清空文字；不得将可见但未确认保存的内容误称为已持久保存。离线本机收录遵循 todo-list 于 2026-10-25 确认的适用映射，联网同步沿后续节点接入。网络中断不作为擅自丢弃用户输入的理由。

## 验收标准

按钮与 Enter 均可提交有效文字；中文选词不会误提交；连续触发同一次提交只产生一条任务；成功后可立即记录下一条；失败保留文字并提供可理解反馈；相同文字的两次主动提交可产生两条不同任务。
