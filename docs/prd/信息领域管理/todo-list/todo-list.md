## 功能描述

todo-list 是个人信息统一工作空间中的待办信息领域。管理待办的内容、可选截止日期和完成状态，优先提供 Windows 悬浮客户端体验。

## 业务规则与约束

- 所有待办专属的概念、机制、交互和验收以本子树为唯一规范位置。
- 已确认：可从悬浮界面快速新增；只有任务内容必填；未完成任务持续显示，截止日期只改变标签；已完成区默认折叠。
- 已确认：可修改内容、设置或清除日期、完成与撤回完成；删除前确认，首个待办版本不提供回收站或撤销删除。
- 具体条件以各原子节点为准，本节点仅概括能力范围。
- 共用的可靠保存、多端一致性等由工作空间机制定义；todo-list 引用这些机制，不复制定义，也不将勾选完成、截止日期等待办规则强加给其他信息领域。
- 既有业务确认保持有效；仅重新归类，不把尚未确定的共享机制、首版范围或实现方案标为已确认。

[已确认] 离线适用范围：本机已有该工作空间时，todo-list 的新增、修改内容、设置或清除截止日期、完成与撤回、删除均可离线使用，沿用各节点已有交互和本机保存规则，不再复制一套离线专属待办操作。需要核对结果或处理冲突的同一任务暂不继续写入，其他任务可正常使用。共用行为引用 [离线操作受理](../../公共机制/统一进度保障/离线记录与补同步/离线操作受理/离线操作受理.md)。

[已确认] 冲突适配：任务文字、截止日期和完成状态可作为独立属性按共同进度比较，同属性不同值需用户选择。删除与编辑冲突时允许用户明确选择恢复原任务并采用编辑结果，作为冲突解决的例外；这不会新增日常回收站或撤销删除入口。具体定义见待办冲突判定。

[已确认] 内置领域映射：创建整个个人信息工作空间时，预先登记并启用一个 todo-list 领域，程序随客户端提供，不单独卸载。用户可按共享领域管理规则停用或再启用；停用后关闭待办业务悬浮入口，任务和已保存待同步进度保留，再启用后回到原任务集合。停用前未保存输入按共享规则先保存或明确放弃。之后新增的每个领域扩展独立定义其内容类型、数据和界面，不自动包含、复制或继承 todo-list 的任务能力。

[已确认] MCP 适用范围：外部 Agent 可通过统一 MCP 入口发现 todo-list 的查询及业务工具。领域已启用且兼容时，可按授权查询未删除任务（含已完成），执行新增、文字修改、日期设置或清除、完成及恢复；删除仍需对具体任务确认，确认通过外部客户端承接文字或语音交互，不强制切回本软件窗口。所有工具使用原任务及同一套业务、保存和冲突规则；停用、结果待确认或冲突不能被强行绕过。单独获得领域管理授权后，也可通过管理工具启停 todo-list，内置程序仍不单独卸载。共享规则见 [MCP内容操作工具](../../MCP工具接入/MCP内容操作工具/MCP内容操作工具.md)和 [MCP领域管理工具](../../MCP工具接入/MCP领域管理工具/MCP领域管理工具.md)，待办不内置另一个 Agent 或单独的权威数据源。

## 交互流程和细节

用户进入待办领域 → 在 Windows 悬浮主界面快速录入 → 回看任务及日期标签 → 查看详情并修改信息或推进状态。具体行为见三个子能力包。

注册、启用和进入遵循信息领域管理四项已确认规则；todo-list 不另建扩展管理流程。AI 操作仍须进入同一套领域业务约束，不能直接绕过任务校验或删除确认。

## 数据范围

待办内容、任务身份、创建时间、可选截止日期、完成状态及当前完成时间。删除后的同步记录是否保留属于后续一致性设计，不构成用户可恢复入口。

引用 [统一进度保障](../../公共机制/统一进度保障/统一进度保障.md)，承接已确认的可靠保存、跨设备更新及冲突处理规则；当前已完成对应共享实现与整体整合。

与通用快速收录、内容回看、内容推进的关联是领域落点映射，不代表彼此互为运行前置依赖。数据迁移和 AI 访问使用工作空间级能力，不在本领域内另建重复规则。

## 边界情况与异常处理

沿用子节点已确认的输入校验、保存失败保留内容、结果不明不误报成功、任务不存在时明确提示等规则。离线、并发及统一位置不可用时的行为遵循统一进度保障已确认的规则。
