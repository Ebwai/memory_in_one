# 待办完成状态切换 [C]

状态：原子节点及具体规则已于 2026-10-25 经用户确认；同日归入 todo-list。

实现状态（2026-10-25）：N23 已实现列表与详情的完成和恢复，成功前保留原状态；恢复移除当前有效完成时间，再完成按新时间排序，重复原操作不反复翻转。

## 功能描述

通过勾选标记完成，或取消勾选将同一条任务恢复为未完成。

## 定位

```text
待办推进
└── 待办完成状态切换 [C] ●
```

## 业务规则与约束

2026-10-26 层级扩展：有未完成后代时，父事项不能完成；全部子待办完成后父事项仍需手动勾选。子事项恢复未完成或移入未完成子树时，受影响的已完成祖先在同次操作中恢复未完成并提示。恢复后遵循同级手动顺序；尚无手动顺序时沿用创建时间。见 [父子完成约束](../../悬浮待办拖动组织/待办目标层级组织/父子完成约束/父子完成约束.md)。

- 用户已要求任务前有完成勾选入口。
- [已确认] 未完成区点击勾选即可完成，无额外确认；详情也提供相同状态入口。
- [已确认] 已完成区展开后可取消勾选，恢复为未完成；详情中也可恢复。
- [已确认] 成功前显示处理中，不允许连续点击将同一次操作重复提交或反复翻转；失败保持原来已确认的状态，明确提示并允许重试。
- 已确认的呈现规则：完成后进入已完成区，恢复后回到未完成区并按创建时间排序，沿用原截止日期重新判定标签。
- [已确认] 再次完成时按本次完成时间进入已完成区排序；不另建任务，不修改文字与截止日期。

## 交互流程和细节

前置条件：任务仍存在，当前无结果未明确的写操作。

1. 用户勾选或取消勾选。
2. 系统显示处理中，等待操作结果。
3. 成功后列表区域与详情状态一致；失败则保留原状态并提示；结果无法确认时提示待确认，不继续提交相反操作。

## 数据范围

任务完成状态和本次完成时间；恢复未完成后不保留当前有效完成时间，不影响任务创建时间。

## 前置能力

共享机制引用：[统一进度保障](../../../../公共机制/统一进度保障/统一进度保障.md)。其产品规则已确认，技术方案及实现尚未开始；待办复用它，不在领域内重复定义。

引用统一进度保障；呈现复用待办显示判定与待办主界面回看。

## 边界情况与异常处理

[已确认] 与其他设备更新或删除冲突时不静默覆盖；同一次重复请求不产生额外状态切换，具体保障由统一进度保障继续细化。切换状态不保存其他尚未提交的编辑内容。

## 验收标准

列表和详情可完成或恢复；完成不删除任务；恢复后仍为同一任务且原日期不变；连续点击不会造成意外翻转；失败不显示虚假的完成结果。
