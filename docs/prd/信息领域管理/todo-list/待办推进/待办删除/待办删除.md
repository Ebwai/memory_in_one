# 待办删除 [C]

状态：既有删除规则及删除与编辑冲突中的明确恢复例外，均已于 2026-10-25 经用户确认。

实现状态（2026-10-25）：N24 已实现具体任务摘要确认、取消、失败保留及成功后退出详情和回看。保留内部删除标记，无回收站或普通撤销入口；跨设备传播和删除冲突处理仍随共享机制整合。

## 功能描述

删除一条不再需要的待办，使其退出可查看和可继续处理的任务集合。

## 定位

```text
待办推进
└── 待办删除 [C] ●
```

## 业务规则与约束

- 用户已要求支持快速删除。
- [已确认] 未完成和已完成任务均可从详情选择删除，确认提示中展示任务内容摘要，供核对对象。
- [已确认] 删除前要求一次明确确认；取消不改变任务。
- [已确认] 首个待办版本不提供回收站或撤销删除，确认时明确告知这一点。内部是否保留用于同步的删除记录留给后续设计，不能等同于用户可恢复入口。
- [已确认] 删除与另一端编辑发生冲突时，允许用户在冲突处理路径明确选择保留删除，或恢复原任务并采用编辑结果。这是特定冲突解决例外，不是普通撤销删除，也不会自动复活旧任务；详见 [待办冲突判定](../../待办冲突判定/待办冲突判定.md)。
- [已确认] 删除成功后关闭该任务详情，任务从未完成区、已完成区和后续回看中退出；不影响其他任务。
- [已确认] 删除失败时任务保留，明确提示并允许重试；结果未明确前暂停同一任务的其他写操作。

## 交互流程和细节

前置条件：任务仍存在，当前无结果未明确的写操作。

1. 用户打开详情，选择删除。
2. 显示任务摘要与无撤销入口的提示，提供确认和取消。
3. 取消则返回原任务；确认则处理中，成功后返回列表，失败保留任务并提示。

## 数据范围

既有无层级实现仅处理被选中的任务。2026-10-26 新需求已确认：有子待办时，以选中事项为根的全部后代也在删除范围内，作为整体全部删除；包括折叠、不可见及已完成后代。此为层级子树删除，不扩展为任意多选批量删除、按完成时间自动清理或其他领域删除。

### 层级删除扩展（2026-10-26 已确认并实现）

- 父事项点击删除后，必须再次明确确认并提醒会连同全部子待办一起删除，不能仅显示单条事项的删除提示。
- 确认显示父事项摘要、全部后代的数量及无普通撤销入口的说明，便于核对影响范围。
- 取消确认时整棵子树保留；确认后整体删除，不将子事项上移，也不留下可见孤儿事项。
- 删除范围由选中事项及其全部后代决定，不删除其祖先或兄弟事项。
- 既有“删除不影响其他任务”的规则，在层级扩展中指不影响子树以外的事项。
- 确认后范围若发生并发变化，不沿旧提示静默扩大删除范围，应重新提示核对。

引用统一进度保障；从待办详情发起，结果更新既有回看入口。

## 边界情况与异常处理

[已确认] 已由其他设备删除时，明确告知任务已不存在并返回列表，不误删其他任务；与其他修改冲突时不静默继续删除，具体解决路径由统一进度保障细化。结果不明时不得宣称已删除；离线旧设备不得将已经删除的任务重新当作新任务同步回来。

## 验收标准

未完成和已完成任务均可删除；确认前可取消；成功后各查看入口均不再显示；失败明确反馈；一次操作不影响其他任务。删除后的跨设备一致性在统一进度保障细化后共同验收。
