# 悬浮待办拖动组织 [C]

状态：2026-10-26 产品规则已确认；已实现，验证结果见 docs/交付验收.md 的递归待办章节。

## 功能描述

在悬浮窗中拖动待办，调整优先顺序或建立可递归的目标层级。

## 定位

```text
悬浮待办拖动组织 [C]
├── [[待办优先顺序调整/待办优先顺序调整.md|待办优先顺序调整]] [C]
└── [[待办目标层级组织/待办目标层级组织.md|待办目标层级组织]] [C]
```

## 业务规则与约束

- [已确认] 每条待办支持拖动；拖到事项之间调整顺序，拖到条目中央成为目标的子待办，拖动时提示操作含义。
- [已确认] 层级可递归，不限于父子两层。
- [已确认] 所有子待办完成后，父待办才能完成。
- [已确认] 父事项及其全部后代作为整体移动或删除；删除父事项前再次提醒并确认整个删除范围，取消不改变任何事项。

## 交互流程和细节

用户在悬浮列表拖动事项 → 看到排序或归属提示 → 释放后按对应能力更新列表。具体边界由两个子能力继续对齐。

## 数据范围

当前工作空间 todo-list 中的事项顺序、父子归属及受影响的完成状态。

## 前置能力

复用既有待办主界面回看、待办推进及统一进度保障，不另建待办数据集合。

## 边界情况与异常处理

跨级移动保留整棵子树，父子完成状态联动及整体删除见子能力及既有待办推进。已完成子事项在未完成父事项下保留原位，根事项完成后整棵树进入已完成区。跨设备竞争时整体结果保留，冲突选择明确说明整组影响，不部分执行子树操作。
