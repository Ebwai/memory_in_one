# 待办冲突判定 [M]

状态：待办专属原子节点及以下规则已于 2026-10-25 经用户确认，包括明确冲突恢复原任务的例外。共享流程不在本节点重复定义。

## 功能描述

说明 todo-list 如何参与工作空间共享冲突机制，定义可独立比较的待办属性及有效结果。

## 定位

```text
todo-list
└── 待办冲突判定 [M] ●
```

## 业务规则与约束

- [已确认] 任务文字、可选截止日期、完成状态可独立比较；具有共同已确认进度时，不同属性改动可同时保留。例如一端改文字、一端改日期可合并。
- [已确认] 同一属性双方改为相同值时可接续；任务文字分别改成不同文字、日期分别改成不同日期、或完成状态出现不兼容选择时转入用户处理，不自动拼接文字。
- [已确认] 清除截止日期是一次明确修改；无变化与主动清除不能混同。任务身份与创建时间不作为用户可选改写字段。
- [已确认] 双方基于同一进度都标记完成时可接续为完成；采用先获得统一位置确认的本次完成时间作为当前有效完成时间，不因另一端相同完成再次到达而重排。完成与恢复的先后涉及不同进度时，按实际共同进度判断，不能仅比较最终勾选值。
- [已确认] 两端都删除时保持删除；一端删除、另一端编辑文字、日期或状态时进入删除冲突。
- [已确认] 用户明确选择保留删除时，原任务继续不出现在正常列表；选择恢复并采用编辑结果时，恢复原任务身份及相应有效属性，不创建第二条任务，呈现仍沿用待办显示判定。
- [已确认] 上述明确冲突恢复是对既有“无日常回收站或撤销删除入口”的特定例外；不允许自动恢复，也不增加常规撤销删除能力。
- [已确认] 手动整理任务文字仍须非空，截止日期可为空或有效日期；当前完成时间与所选完成状态一致，不能让未完成任务保留当前有效完成时间。

## 交互流程和细节

共享机制调用待办属性含义进行比较 → 可独立合并则接续原任务 → 冲突时使用共享差异与选择入口 → 用户明确保存有效结果 → 按原任务与既有显示规则继续使用。

## 数据范围

同一任务的文字、截止日期、完成状态及其对应完成时间、删除意图。不同任务即使文字相同也不因此合并。

## 前置能力

沿用待办内容、日期、完成与删除节点的已有有效性要求。为共享 [并发差异判定与自动合并](../../../公共机制/统一进度保障/并发修改与冲突处理/并发差异判定与自动合并/并发差异判定与自动合并.md)提供领域含义；比较与选择流程仍由共享机制负责，本节点不反向要求共享流程已执行才可给出属性含义。

## 边界情况与异常处理

[已确认] 缺少共同进度时不尝试猜测自动合并；若任务文字无法读到或选择结果无效，保留材料并提示；恢复已删除任务必须经过明确冲突解决，离线旧副本不自动恢复任务。

## 验收标准

文字与日期并发修改可保留双方；同属性不同结果转入共享处理；清除日期不被忽略；双方完成不因重复到达而反复改变排序；删除与编辑可由用户明确决定保留删除或恢复同一任务，无自动复活或多建任务。
