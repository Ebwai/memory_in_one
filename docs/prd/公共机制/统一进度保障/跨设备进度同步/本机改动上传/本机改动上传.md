# 本机改动上传 [M]

状态：原子节点及以下具体规则已于 2026-10-25 经用户确认。

## 功能描述

将本机已经可靠保存的改动提交到同一工作空间的统一位置，并接续其明确结果。

## 定位

```text
跨设备进度同步
└── 本机改动上传 [M] ●
```

## 业务规则与约束

- [已确认] 仅上传已可靠保存在本机的操作，新增与更新都保持原内容身份，重复同步不另建独立副本。
- [已确认] 统一位置明确接受当前改动后，才将该改动标记为已同步；较早改动的成功不能清除之后的新改动。
- [已确认] 同一内容多次改动应保持其先后含义，不因传送先后而退回旧成果；不同独立内容可分别完成，不因一条失败误报全部失败或阻塞全部内容。
- [已确认] 对方已有并发改动时交由冲突机制处理，不以整份覆盖消除差异。上传不擅自变更工作空间归属。

## 交互流程和细节

前置条件：已有本机可靠保存的待同步操作，当前可访问已选定工作空间。

同步触发 → 向统一位置提交原操作 → 按接受、失败、待确认或冲突更新该改动状态；已知成功不重复执行。用户无需重新输入已有内容。

## 数据范围

当前工作空间内已保存的新增、更新和领域允许的删除动作，不包含未提交输入或其他工作空间。

## 前置能力

复用 [可靠保存与结果确认](../../可靠保存与结果确认/可靠保存与结果确认.md)，引用 [并发修改与冲突处理](../../并发修改与冲突处理/并发修改与冲突处理.md)。删除结果传播复用本能力，不另建上传方式。

## 边界情况与异常处理

[已确认] 中断或统一位置不可用时保留待同步操作；结果不明时核对原操作；部分失败保留各自结果，不清除尚未完成改动。同步期间产生的新改动仍需单独获得确认。

## 验收标准

新增和更新可在统一位置接续，重复触发不重复创建；旧操作响应不覆盖新改动；失败保留本机内容和待同步进度；无冲突的独立改动不被其他内容的冲突阻塞。
