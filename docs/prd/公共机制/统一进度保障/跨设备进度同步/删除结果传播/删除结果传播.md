# 删除结果传播 [M]

状态：原子节点及以下具体规则已于 2026-10-25 经用户确认。

## 功能描述

让统一位置确认的删除结果在其他设备接续，并防止旧副本重新带回已删除内容。

## 定位

```text
跨设备进度同步
└── 删除结果传播 [M] ●
```

## 业务规则与约束

- [已确认] 领域允许的删除在本机保存后，沿既有同步能力传送至统一位置；其他设备取得删除结果后，按领域规则退出该内容的正常查看入口。
- [已确认] 旧设备重新连接时识别已确认删除的原内容，不把它当作新内容再次上传；用户主动创建相同文字的新内容不属于旧内容复活。
- [已确认] 远端删除遇到本机未同步编辑或尚未提交的输入时，保留待处理成果并交给冲突机制，不能静默丢弃，也不能自动撤销已经确认的删除。
- [已确认] 删除未同步或结果不明时明确标记未完成的同步结果，应用重启不能将它误当作已完成全局删除。
- 删除前确认、回收站或撤销等领域生命周期仍由各领域定义；本机制不把 todo-list 的无回收站规则推广到其他领域。

## 交互流程和细节

用户按领域规则删除 → 本机保存删除结果 → 既有上传能力提交 → 统一位置确认 → 其他设备通过既有获取能力接续；遇到本机待处理改动时转入冲突处理。

## 数据范围

同一内容的删除结果、相关未同步操作，以及用于识别旧内容的持续归属。不在 PRD 指定删除标记的数据格式或清理策略。

## 前置能力

复用同级 [本机改动上传](../本机改动上传/本机改动上传.md)、[统一进度获取](../统一进度获取/统一进度获取.md)，引用共享 [并发修改与冲突处理](../../并发修改与冲突处理/并发修改与冲突处理.md)。

## 边界情况与异常处理

[已确认] 重复接收同一删除不影响其他内容。长期离线设备补同步后也不使旧内容复活；冲突的最终解决方式留给冲突机制，不能把保留待处理成果解释为已自动恢复原内容。

## 验收标准

一端删除并获得统一位置确认后，其他设备接续删除；旧设备重连不复活旧内容；重复传播只影响原内容；与未同步编辑冲突时不丢弃编辑也不自动恢复，状态明确可处理。
