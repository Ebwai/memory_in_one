# 冲突解决选择 [C]

状态：原子节点及以下具体规则已于 2026-10-25 经用户确认。

## 功能描述

让用户理解同一内容的差异，明确选择保留的结果，最终接续一份可以继续处理的权威进度。

## 定位

```text
并发修改与冲突处理
└── 冲突解决选择 [C] ●
```

## 业务规则与约束

- [已确认] 从领域内容的冲突提示进入，显示本机与统一位置的差异，条件允许时提供共同进度供比较，不将设备时钟先后作为胜出依据。
- [已确认] 普通编辑冲突可采用本机、采用统一位置或手动整理；明确提交选择前可退出，材料继续保留。手动整理必须符合领域校验。
- [已确认] 删除与编辑冲突时，明确选择保留删除，或恢复原内容并采用编辑结果；不默认选定恢复，也不另建新内容来掩盖冲突。恢复是否具备领域有效状态由领域定义。
- [已确认] 选择先在本机可靠保存；统一位置可达且其相关进度仍符合当前比较时，再接受选择结果。远端再次变化时重新比较，保留用户整理内容，不强制覆盖。
- [已确认] 离线可以查看、整理并保存待提交选择，但只有统一位置确认后才标记全局冲突已解决；此前同一内容维持待处理状态。
- [已确认] 选择的一方被放弃必须是用户明确提交的结果，不静默丢弃；不额外提供“永久保留两条独立内容”作为默认解决方式。

## 交互流程和细节

前置条件：已可靠保留待处理冲突。

用户进入冲突详情 → 查看差异 → 选择或整理结果 → 明确保存解决结果 → 本机保存 → 核对统一位置最新进度 → 可接受时确认并交回同步。结果不明沿既有结果核对机制接续；失败保留整理内容。

## 数据范围

同一原内容的冲突材料、用户选择及解决结果。另一设备取得解决结果时，若仍有额外未合并改动，继续按实际差异处理，不让旧选择覆盖新成果。

## 前置能力

引用同级冲突成果保留、差异判定及领域有效性要求；本机保存引用 [可靠保存与结果确认](../../可靠保存与结果确认/可靠保存与结果确认.md)。本节点给出选择结果及接受条件，由现有同步能力传送，不重复定义同步渠道。

## 边界情况与异常处理

[已确认] 冲突展示不完整时不提供会误导用户的全量覆盖结论；保存失败不丢整理内容；处理期间有新更新则提示比较已变化，允许继续整理；删除选择仍遵循领域确认规则。

## 验收标准

三种普通编辑选择均可完成；退出后可接续；编辑与删除需要明确选择，不自动复活；离线选择不误标全局解决；新更新不被过时选择覆盖；成功后结果仍属于同一内容。
