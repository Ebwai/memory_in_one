# 并发修改与冲突处理 [M]

状态：节点、三个直接子节点及具体规则均已于 2026-10-25 经用户确认，非原子节点。

## 功能描述

当多个设备或入口基于不同进度修改同一份内容时，识别需要处理的冲突并保护未合并成果，最终形成可继续推进的一份权威结果。

## 业务规则与约束

- 已知输入：产品希望接续同一份进度，避免成果分裂；todo-list 已确认遇到其他设备修改不静默覆盖，删除冲突也不能静默继续执行。
- [已确认] 不把“最后到达的写入”默认当作可以丢弃另一方成果的理由；无法安全合并的内容保留可处理状态并明确反馈。
- [已确认] 最终解决结果回到同一条内容及其进度，冲突保护不默认把它永久分裂成多个互不关联的新任务或独立记录。
- [已确认] 存在共同已确认进度、且领域声明各属性独立时，自动接续不同属性的改动或同属性的相同结果；同属性不同结果不按最后到达决定，也不自动拼接文字。
- [已确认] 无法安全合并时，可靠保留待处理成果，用户可采用本机、采用统一位置或手动整理后明确保存。删除与编辑冲突时，明确选择保留删除或恢复原内容并采用编辑结果，不能自动复活。
- 具体领域如何判断属性独立及恢复后状态，由领域适配定义；待办规则见 todo-list 的待办冲突判定。

## 交互流程和细节

多入口提交不同更新 → 判断能否安全合并 → 可合并则交由既有保存和同步接续；否则先保留成果、标记待处理 → 用户查看差异并明确选择 → 核对当前进度仍匹配后保存选择并交回同步。选择期间进度再次变化时重新比较，不把过时选择强加到新成果上。

## 数据范围

同一份内容的相关改动、尚未合并成果及解决选择。领域状态含义仍由领域定义，不在本机制新增待办专属状态。

## 前置能力

差异判定使用领域声明的属性含义及可比较的共同进度；成果保留复用可靠本机保存；解决选择使用已保留成果及领域有效性要求。同步与离线调用本能力，本能力给出可提交结果，不反向承担同步传输，避免产品能力循环。

## 边界情况与异常处理

[已确认] 缺少比较依据时保守进入冲突，不擅自推断一方胜出；处理过程中关闭应用后仍可找回待处理成果；选择结果遇到新进度时保留用户整理内容并刷新比较；同一内容暂停普通写操作，其他独立内容继续使用。未来 Agent 参与时同样遵守共享冲突原则，接入范围仍由 MCP工具接入确定。

## 验收路径

[已确认] 不同独立属性可合并，同属性不同值明确冲突；冲突内容重启不丢；用户可明确选择并使结果回到原内容；删除与编辑不静默丢弃或自动恢复；处理期间再有更新不会被旧选择覆盖。

## 后续已知输入

todo-list 已确认的原任务身份、完成状态切换及删除语义是本机制的使用约束；具体任务规则继续留在 todo-list，后续按需定义领域如何参与共享冲突处理。
