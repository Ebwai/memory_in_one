# 本机内容持久保存 [M]

状态：原子节点及以下具体规则已于 2026-10-25 经用户确认。

实现状态：N01 保存底座已于 2026-10-25 完成。内容、删除标记及待同步操作同事务保存，重启可读取；原保存底座包含 17 项测试，接入 N02 后 Node 与 Electron 内置运行时各通过 30 项。界面反馈和实际上传在后续节点接入后验收。技术语义与证据见 [TDD 导航](../../../../../TDD.md)。

## 功能描述

将用户提交的内容及尚需同步的进度可靠保存在本机，使应用重新打开后可以接续使用。

## 定位

```text
可靠保存与结果确认
└── 本机内容持久保存 [M] ●
```

## 业务规则与约束

- [已确认] 仅显示在界面里不代表已保存；本机可靠保存的离线记录在应用重启后仍可找回。
- [已确认] 一次提交的内容与其待同步进度作为一个完整结果保留，不出现内容已经显示保存成功、但重启后不知道还需要同步的情况。
- [已确认] 本机可靠保存成功即可返回本机保存成功，领域可清空已提交输入并允许继续记录，不等待网络；是否已同步另外反馈。
- [已确认] 本机保存失败不改变此前已保存内容，不清空当前输入，不向统一位置发送这个尚未在本机可靠留下的新操作。
- [已确认] 对领域允许的更新或删除，同样保留已保存结果及必要待同步进度，不能在应用重启后将本机已保存的删除误当作从未发生。
- 哪些动作允许离线执行，由离线记录与补同步确认；本节点不扩大领域可执行动作范围。

## 交互流程和细节

用户提交一个领域允许的动作 → 本机保存处理中 → 成功则明确本机已保存并交给状态呈现；失败则保留输入和此前成果，反馈失败。应用重新打开时，恢复已确认保存的内容及待同步进度。

## 数据范围

当前工作空间、所属领域的内容以及相关操作结果和待同步进度。不同领域的数据含义由领域定义，不在本节点加入待办专属字段。

## 前置能力

当前无已定义的其他产品前置节点。为同级的结果恢复及状态呈现提供可靠保存结果；部署和存放位置的选择不是本节点的交互职责。

## 边界情况与异常处理

[已确认] 保存被中断时，下次进入只能确认此前完整保存的结果，不能误报部分写入已经成功。发生失败时不展示技术堆栈，只说明未能保存及可继续处理的动作。未提交输入的跨重启草稿恢复不由本节点新增承诺。

## 验收标准

本机成功后即使暂时无法同步、退出并重新打开，内容与待同步进度仍可接续；本机失败保留输入和之前内容；应用不会把部分结果当作完整成功；未确认成功的动作不被悄悄继续提交到统一位置。
