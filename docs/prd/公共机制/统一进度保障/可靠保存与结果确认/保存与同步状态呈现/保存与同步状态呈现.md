# 保存与同步状态呈现 [C]

## 功能描述

让用户明确知道当前内容是否已保存在本机、是否已到达统一位置，以及是否需要处理问题。具体控件可适应各信息领域，不强制采用待办界面。

## 定位

```text
可靠保存与结果确认
└── 保存与同步状态呈现 [C] ●
```

## 业务规则与约束

[已确认] 状态含义如下，表中描述的是当前这次改动：

| 状态 | 用户应理解的结果 |
|---|---|
| 未保存／本机保存失败 | 本次改动尚未确认在本机可靠留下，输入保留 |
| 本机保存中 | 尚无确定的保存结果，不能显示已保存 |
| 已保存在本机，待同步 | 本机可靠保存已确认，尚未确认统一位置接受 |
| 同步中 | 本机已保存，正在向统一位置确认或传送 |
| 已同步至统一位置 | 统一位置已确认当前改动，不表示每台其他设备都已取得 |
| 同步失败 | 本机内容仍保留，本次同步未完成，可继续处理 |
| 结果待确认 | 尚不能断定这次操作成功或失败，需要沿原操作核对 |
| 存在冲突，待处理 | 不能直接作为同步完成，需要按冲突机制处理 |

- [已确认] 一次内容后续产生新改动时，旧改动的已同步结果不能让新改动也显示已同步。
- [已确认] 同步失败不称为本机保存失败，不要求用户重新输入已经保存在本机的内容。
- [已确认] 本机内容未保存或结果不明时，不能静默清空当前输入；本机成功后的清空动作遵循领域规则。
- [已确认] “已保存在本机，待同步”不是结果不明；是否还可继续离线编辑等操作，仍由对应领域和离线机制规定。

## 交互流程和细节

用户提交后看到保存进展 → 本机成功后看到待同步等状态 → 后续按明确结果更新状态；出现失败、结果不明或冲突时，呈现说明和相应的继续处理入口。重试动作由同级重复提交与结果恢复承接，冲突解决交给对应机制。

## 数据范围

内容当前改动及其保存、同步、结果核对状态。不将任一条内容的成功夸大为工作空间全部内容已同步。

## 前置能力

引用同级 [本机内容持久保存](../本机内容持久保存/本机内容持久保存.md)和 [重复提交与结果恢复](../重复提交与结果恢复/重复提交与结果恢复.md)。后续同步和冲突机制使用本节点的结果含义反馈状态；本节点不反向承担同步传输或冲突处理。

## 边界情况与异常处理

[已确认] 暂时无法取得统一位置状态时，不假装最新内容为空，也不保留一个会误导用户的已同步标记。已保存的本机内容仍可展示。提示不能只依赖颜色，需有可理解的文字含义。

## 验收标准

用户能区分本机失败与同步失败、待同步与已同步；重启后状态符合已确认的保存结果；新改动不会被旧成功结果误标为已同步；同步至统一位置不被表述为所有设备已更新。
