# 重复提交与结果恢复 [M]

状态：原子节点及以下具体规则已于 2026-10-25 经用户确认。

实现状态：N02 本机能力已于 2026-10-25 完成。同一操作等价重试返回原保存结果，支持响应丢失和重启后核对；旧回执不覆盖后续成果，不同动作不能复用原操作身份。Node 与 Electron 内置运行时各通过 30 项测试。服务器结果核对及界面接入仍在后续节点验收，技术语义见 [TDD 导航](../../../../../TDD.md)。

## 功能描述

在重复触发、超时、响应丢失或重新进入应用时，接续同一次操作的结果，避免重复内容、意外反复执行或丢失已保存成果。

## 定位

```text
可靠保存与结果确认
└── 重复提交与结果恢复 [M] ●
```

## 业务规则与约束

- [已确认] 连续触发同一次尚未结束的提交，只产生一次动作；重试沿用同一次动作，不把它解释为用户又新增或切换了一次状态。
- [已确认] 明确失败时可沿原操作重试；结果不明时先核对原操作的结果，不能仅因没有收到响应就当作从未发生。
- [已确认] 原操作已成功时返回其已确认结果，不重复执行；原操作仍未确认时保留待确认状态，提示可再次核对。
- [已确认] 本机已保存但远端结果不明时，本机内容不丢失，仍能在应用重启后找回并继续核对。
- [已确认] 恢复出的旧结果不得覆盖更新的内容或把新改动误标为已同步。已由统一位置删除或被并发修改的内容交给同步与冲突机制，不能强行作为新增恢复。
- [已确认] 用户在一次动作结束后主动再次提交相同文字，属于新动作，不按文字自动合并为一次。
- 本机保存尚未确认时的并发触发限制与领域已有规则一致；已明确本机成功、仅等待同步的操作不等同于本机保存结果不明。

## 交互流程和细节

用户提交 → 若得到明确结果则正常继续 → 若结果不明则提示核对 → 取得结果后接续原操作；失败可重试，已成功不再执行。应用重新打开时接续已经可靠留下的操作，而不是无条件再次执行一遍。

## 数据范围

当前工作空间内一次操作的待处理内容、可确认结果与接续进度，不按内容文字判断是否同一次操作。

## 前置能力

引用同级 [本机内容持久保存](../本机内容持久保存/本机内容持久保存.md)。向同步与离线机制提供同一次操作的重试与恢复含义，不在此决定网络传输、重试间隔或领域冲突解决策略。

## 边界情况与异常处理

[已确认] 统一位置暂时不可达时不无限阻塞整个界面，不误报成功；保留可确认的本机结果，给出仍待确认的反馈。删除等领域动作的结果核对不能误执行成其他动作。最终操作冲突的解决规则由并发修改与冲突处理继续细化。

## 验收标准

连续点击、响应丢失后核对、恢复后重试和重新进入应用，不让同一次新增产生两条内容，也不让同一次状态切换反复执行；两次主动提交相同文字仍可产生两份独立内容；旧结果不覆盖新改动。
