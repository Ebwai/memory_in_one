# MRD：个人信息统一工作空间

状态：用户已于 2026-10-24 确认。来源：用户原始构想，原文保留于 `docs/原始需求.txt`。

## 产品初衷

想法往往产生于碎片时间，而深入思考需要完整的时间。记录时的设备、地点与时间不应成为信息留存的障碍。这个产品希望连接“当下快速记录”和“未来继续推进”，让临时产生的想法能够积累成持续的思考与行动。

## 核心问题

- 信息散落在不同设备和记录入口中，后续难以集中找回。
- 记录和深入思考之间缺少连续性，可能重复思考同一件事情，产生难以管理的分散版本。
- 不同类型的信息具有不同用途，单一组织方式难以承载全部个人信息。
- AI 与 Agent 需要可信的个人信息来源，才能基于一致的上下文开展工作。
- 信息若绑定某台设备或服务器，就难以在迁移环境后持续积累。

## 核心价值与设计原则

### 先留下，再整理

记录应适应碎片时间。用户可以先保留内容，再在有时间时补充背景、归纳和深入思考；整理负担不应阻止记录发生。

### 统一的信息权威来源

不同设备访问和推进的是同一份信息及其当前进度。持续思考应建立在已有成果之上，避免多个互不关联的副本成为并行事实来源。这不意味着禁止保留可追溯的历史。

### 用户掌握数据与存放环境

信息可以存放在用户自己的电脑或购买的服务器资源中。用户能够携带完整数据迁移环境并恢复使用，避免数据被绑定在单一部署位置。

### 统一工作空间承载多种信息领域

待办、项目想法等内容共享统一的信息归属，同时允许不同类型采用适合自身的组织方式。未来扩展新的信息领域，不应破坏已有信息的连续性。

### 面向人与 Agent 的共同信息基础

统一的信息来源既服务用户查看与推进工作，也为 AI 参考信息及 Agent 管理工作提供可信上下文。具体接入方式与权限边界在后续需求和设计阶段确定。

## 首个落地方向

以待办事项作为首个信息领域，优先服务 Windows 上的日常记录场景，用实际使用验证“快速留下、集中找回、持续推进”的价值。跨设备、多领域和数据可迁移是整体产品方向；各阶段交付范围在 PRD 中明确。

## 待后续需求阶段明确

- “插件”是否作为正式产品术语，或采用“信息领域”等名称。
- 设置任务属性后，任务在日常视图中的显示规则；原始描述关于截止日期的句子尚未完整。
- 首版跨设备使用、离线使用与 Agent 管理的交付边界。

以上问题不改变本 MRD 的产品初衷，也不预设技术方案。


### 新增的需求
- [ ] To do list 的每一条都可以在悬浮窗里的待办事项列表之间拖动，并且拖动主要有两个意义：
1. 快速调整选中待办事项的优先级。
2. 当选中的待办事项被拖动到另一个待办事项条的位置时，它会在被覆盖的待办事项下方，添加一个属于该事项的子待办事项。也就是说，这可以用来表示待办事项的依赖关系。上层呢相当于一个比较大的目标，而子目标相当于是更细致一点的目标，这个可以无限地递归下去，不只局限于子母两层，类似于文件夹的那种结构
- [ ] 需要有一些模板，比如说项目模板，那么用户在创建新的插件域的时候就可以直接复用这个模板,可以创建模板，比如说有关于项目的插件模板，这个里面会分为几个块进行记录，第一个是项目的待办事项，第二个是关于项目的一些想法。想法和待办事项的区别在于，待办事项更为具体的，而想法可能是更加原始的一些关于项目的内容。并且对于插件，可以提供给同一个记忆域一个属于这个插件的MCP接口，比如说，关于项目的这个模板里，就可以在待办事项里添加一条，或者是在关于项目的想法的块中添加一条
