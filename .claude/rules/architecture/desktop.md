### 定位与职责

提供悬浮待办与工作空间管理界面，并托管设备本机副本、同步执行和系统资源。

关联 PRD：Windows悬浮收录入口、待办快速收录、待办回看、待办推进、领域目录与进入、保存与同步状态呈现。

2026-10-26 增量关联：悬浮待办拖动组织、待办优先顺序调整、待办归属调整、待办层级回看、父子完成约束。renderer 拥有拖放提示、展开状态及删除确认快照；host 经共享核心组织整体提交。模块边界、数据所有权和依赖方向不变，见 [递归待办 TDD](../tdd/todo-tree.md)。

所有权：窗口及焦点归 host，暂未提交输入归 renderer，本机持久数据由 host 组装的核心及存储适配器管理。renderer 的乐观显示不能生成保存成功事实。

2026-10-28 增加桌面应用更新：host 拥有版本发现、下载校验和安装状态，renderer 只展示并发出窄动作；deploy/desktop 的独立助手在既有退出保护完成后替换程序并处理启动回退。程序目录与持久数据严格分离；更新不持有工作空间凭据，也不更新远端服务。详见 [桌面更新 TDD](../tdd/desktop-update.md)。

### 内部组成

| 子目录 | 职责 |
|---|---|
| renderer/ | React 工作空间界面和领域视图；只持有展示状态与未提交输入 |
| bridge/ | preload 的窄能力桥接，校验请求及返回可展示结果 |
| host/ | Electron 主进程入口、核心组装、本机服务托管与系统资源边界 |

业务内核、todo-list 规则、数据库与同步适配器来自共享包，不复制到此。host 的数据库和导出重任务运行在专用执行上下文，具体进程安排在 N01 TDD 落实。

当前三个目录已由 N03 保存状态演示建立：host 组装真实本机保存服务，bridge 只暴露演示的保存、核对与读取，renderer 消费共享 ui 状态组件。数据库仍在原 worker 内。该 N03 演示保持独立；领域管理、悬浮待办和本机初始化服务由下述正式工作空间入口承接。当前行为及实测锚点见 [N03 TDD](../tdd/save-status.md)。

### 依赖与联动

- renderer 依赖共享 UI 及可序列化契约，不导入文件系统、数据库、网络凭据或核心写执行器。
- bridge 不暴露任意 IPC、SQL、文件路径读写或执行命令；host 复核调用来源、空间和动作。
- host 先通过核心完成本机事务，再向 renderer 发送保存结果；向统一位置上传是后续独立状态。
- 悬浮窗口和管理窗口使用同一份本机应用服务；切换窗口不会建立第二套待办数据。
- 领域停用与程序移除先协调所属视图的未提交输入；业务决定由核心给出，界面承接用户选择。
- 自定义扩展视图采用宿主提供的声明式组件，扩展包内容不作为任意 HTML 或 preload 代码运行。

### 架构级约束与不变量

| 约束 | 保护范围 | 保障方式 |
|---|---|---|
| Node 集成关闭，context isolation 与渲染 sandbox 开启 | renderer 与宿主权限 | 启动配置及打包检查 |
| 不加载远端网页作为业务界面；外部导航须由 host 明确处理 | 导航与凭据 | 内容策略、导航及窗口创建限制 |
| 本机受理与待同步材料同事务提交 | host、核心、存储 | 失败和重启测试 |
| 输入仅在本机成功后清空 | renderer、bridge、host | 入口故障验收 |

### 当前初始化入口

N05 增加独立 workspace-main 宿主和创建界面。宿主托管本机初始化服务，创建确认后保存绑定，客户端副本与权威文件分离；远端凭据只由主进程加密留存。renderer 临时承接用户主动输入的凭据，不从持久层读取原秘密。该入口与原保存演示隔离。N07–N15 已接入领域目录、声明式扩展和内置待办快速收录；绑定后的默认待办窗口和管理界面共用同一 BrowserWindow、同一副本及主进程应用服务。窗口和草稿生命周期由 host、bridge、renderer 配合维护，技术语义见 [领域生命周期](../tdd/domain-registration.md) 及 [待办收录](../tdd/todo-capture.md)。N16–N20 在同一副本上增加只读回看、稳定列表和详情，日期判定仍归独立待办包；不新增业务数据所有者或新的写入口，技术语义见 [待办回看](../tdd/todo-review.md)。N21–N25 通过领域动作和核心原操作核对实现待办推进；详情草稿及按任务请求状态仍由当前窗口托管，原存储事实源和模块依赖方向不变，见 [待办推进](../tdd/todo-progression.md)。

### 技术选型与非功能约束

Electron 负责拖动、置顶和窗口生命周期；React 负责界面。置顶切换通过窗口端口执行，领域核心不感知 Electron。平台细节留在 host，避免未来桌面平台切换污染领域规则。

选型依据见顶层架构；本轮不新增快捷键、自启、托盘或提醒等产品承诺。


N26–N30 沿用同一入口加入内容推进整合及冲突提示/解决界面。renderer 管理整理输入与草稿保护，host 绑定空间和待办领域，只允许保存选择；共同进度和权威回执不由 renderer 输入。冲突材料和普通写入门禁仍归核心/事务适配器，技术语义见 [冲突接续](../tdd/conflicts.md)。
