# 待办拖动与递归目标

状态：2026-10-26 已实现；实测范围见交付验收的递归待办章节。PRD 为悬浮待办拖动组织；沿既有领域解释、核心提交、适配器持久化及桌面呈现边界扩展，不另设事实源。

## 模块概览与 API 导航

独立待办包负责父级、同级位置、无环约束、子树删除及祖先恢复的纯计算。核心和存储增加通用多记录提交能力；不将待办规则写入数据库适配器。实际契约见 contracts 的 LocalPersistence、DomainHandler、UploadRequest。

## 数据模型

父级及同级位置为待办可选属性；旧任务缺失属性时作为顶层，保留创建时间顺序。树形投影由记录派生，不复制业务事项。展开状态仅属于界面。

## 关键流程与事务

拖动、完成、恢复或删除先根据完整领域快照计算结果，再以领域快照及登记版本作为竞争检查，一次提交全部受影响记录。删除确认冻结子树的身份与版本，范围变化后重新确认。子树操作不能通过循环发起若干互不关联的用户操作。

多记录本机操作用保留命名空间 batch1 的稳定操作身份标识分组、序号、数量及请求摘要；同一原操作重试先核对持久回执。组信息随原操作材料导出恢复，无新增外部事实文件。

上传将同组操作冻结为单一复合请求。服务对完整结果调用领域集合校验，并在领域快照未变化的同一事务中提交全部版本及原回执。普通单条写入也须通过集合校验，MCP 不能绕过父子约束。

历史获取把复合提交作为一组返回并原子导入，游标只在整组处理后推进。并发或编辑保护保留本机成果，不能部分覆盖同组记录。

HTTP 整体上传前检查 atomicProtocol=1 能力；旧服务不接受未经能力确认的整体操作。树形历史获取也要求客户端声明整体协议，避免旧客户端只取到主事项。复合回执携带关联版本，主事项版本最后写入，作为整组历史游标。分组身份和原回执均保存在既有操作/同步表中，快照无需新增表或额外业务文件。

整组竞争保留 atomicGroup 冲突材料及全部原操作。界面明确选择范围；解决请求先持久冻结，再整组提交和整组接收，失去回执可按原请求接续。另一端在删除确认后新增子事项时，集合校验拒绝扩大删除，转为可恢复的整体冲突。获取遇到尚未处理的整组本机成果时暂停该组导入，不推进游标或部分覆盖。

关联的后续本机分组纳入冲突闭包，界面明确展示完整影响数。相关事项暂停普通修改。远端整体删除与本机子事项编辑相遇时，保留原树和编辑内容；明确恢复时恢复整组并应用整理结果。其他事项尚有独立未提交编辑时，不清理或覆盖其输入。已经确认的旧分组回声只推进游标，不反复制造编辑冲突。

## 状态与失败

未完成子事项阻止父事项完成；恢复子事项或移入未完成子树时，在同次提交中恢复已完成祖先。排序和归属一起变化。未知结果保留原操作身份供核对；已知失败不伪装成功。
