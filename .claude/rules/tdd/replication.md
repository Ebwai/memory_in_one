# 同步、删除传播与离线接续（N32–N40）

状态：2026-10-26 已实现并通过最终全量回归，后续 N41–N43 已完成统一进度保障、多端记录与持续推进及 todo-list 整体验收。

## 模块概览

承接 core operations/replication、adapters sqlite/connection 与 server composition/transport 的既定边界。复用 N31 的共同进度比较、冲突材料与明确解决选择。权威服务拥有确认历史与幂等回执；客户端拥有可靠本机操作、发送快照及确认副本。

## API 与状态语义

UploadRequest 固定空间、权威身份、内容及原操作 ID。第一次发送前将完整请求保存到原副本；网络中断后重发同一请求。服务先核对原回执，再验证领域、基准版本和当前版本；确认事实及去重回执在同一事务内提交。

## 顺序、一致性与失败

每条本机操作在原保存事务中记住共同进度、前一条本机操作及修改前内容。上传按原序列执行，前一操作被接受后，后一操作只把自己的字段差异应用到前一确认结果，避免抹掉前一自动合并保留下来的其他字段。请求一旦冻结就不可重算。较旧确认不替换之后的本机写入；独立内容不因另一条冲突或业务失败停止。

无共同依据不猜测覆盖；服务缺领域、停用或版本不兼容返回拒绝，原本机内容保留。不能安全合并时通过 N31 保留冲突再反馈。明确解决选择通过带预期版本的同一权威执行器提交，普通旧副本不能自动复活删除。

## 持久化与迁移

原不可变 pending_operations 保留作为重试依据。v3 增量增加权威历史/回执、本机确认副本、操作发送状态及游标。历史 v1/v2 操作保守回填前后关系，不凭本机时间伪造共同已确认进度。回执、当前内容与确认元数据更新均由 SQLite worker 事务维护。

实现锚点：contracts/replication.ts、core/operations/authority-service.ts、core/replication/engine.ts、adapters/sqlite/replication-database.ts、adapters/connection/http-sync.ts。N33–N40 的接续语义及验收见下文。

## 统一进度获取与删除传播（N33–N34）

权威历史以服务分配的单调进度分页；身份、顺序和页尾游标须完整匹配。版本先在本机事务中写入确认副本、必要当前投影和游标，不能先推进游标再保存内容。旧历史页不使已确认的新版本倒退。导入产生带原身份的内部操作快照，供现有详情和编辑依据读取，但状态为 imported，绝不当成新增业务操作上传。

有未同步成果时，接续使用共同依据及领域属性语义；有活跃编辑时保留原编辑输入，进入可处理冲突。接续重试重新核对本机序号，事务门禁防止拉取与本机写入竞争。缺程序的未知领域可保留原始载荷，但不能凭同步安装外部程序或开放业务写入。

null 是持久删除标记，旧设备不能把它当成从未存在；普通写入不能恢复统一位置已确认的删除。明确解决选择才允许恢复原身份。双方删除可接续，删除与编辑则保留材料。创建相同文字但新身份仍是新内容。

## 触发、刷新及整合（N35–N36）

desktop/host/sync-features.ts 是窗口进程内的单一调度者；启动/接入、保存尝试后的可靠操作、恢复运行及 renderer 的 online/focus 信号触发同一队列。反复“立即同步”共用正在执行的 Promise；写入期间的后续触发会接续下一轮，不并行上传同一批。常驻运行时每 10 秒主动接续，挂起和退出不承诺后台同步。停止时先排空同步，再关闭本机权威服务；服务也先等待正在执行的应用请求再释放独占租约。

SyncStatus 只消费主进程状态，不取得凭据。pending、uncertain、conflict 与业务拒绝分开；有任何未完成改动都不显示整体已同步。最新获取失败保留此前列表，不用空列表伪装成功。已获确认仅表示该统一位置接收以及本机已取得当前进度，不宣称所有设备都已同步。renderer 收到副本更新信号后重读本机列表，已有编辑输入不随重读替换。

tests/e2e/replication.test.mjs 启动两个真实 Electron 客户端、独立副本和同一个 HTTP 服务，验证保存自动上传、另一个客户端无需手动刷新在 30 秒目标内取得新增、立即同步、重启及补同步。此结果限于测试的正常回环联通环境，不等同于公网、移动端或挂起状态的性能保证。

## 离线访问、操作及恢复（N37–N40）

本机领域、内容和待同步材料均读取原绑定副本；网络失败不改变空间身份，不建立替代空间。已有领域的动作校验与在线相同，普通待同步内容允许继续处理；本机保存未成功不得说成已保存待同步。无可用副本且未取得权威进度时明确显示暂无本机内容，不推断服务器为空。

发送前冻结请求，失去回执后保留同一请求并标记 uncertain；同内容新写入在 SQLite 事务内暂停，其他内容仍可受理。正在正常发送仅为 syncing，不把它误判为结果未知而拒绝快速连续编辑。进程恢复时将曾冻结、未获回执且未明确拒绝的请求转为待核对，再通过原 ID 接续。原回执只确认对应操作，不能清除后续本机成果。即使拉取到与未知请求相同的内容，也不凭内容相等冒充原操作已确认或制造无依据冲突。

v4 增量加入 editor_drafts 与不确定发送标记。进入已有内容编辑前保护原版本；后续输入写入独立整理材料，不作为业务内容自动上传。远端更新/删除与当前整理相遇时保留 editorValue 和双方进度，正常写入暂停，待用户明确处理。取消、放弃与成功提交清理相应编辑保护；异步放弃完成后才执行关闭/切换，防止残留保护或丢输入。todo-list 继续负责字段合法性；自定义领域通过已声明字段呈现和校验，不继承待办完成属性。

恢复连接或重启后仍复用同一上传/获取/冲突链；一次冲突选择失败不阻塞其他独立成果。领域登记与启用状态同步，但其他客户端的自定义程序安装状态不跟随；内置待办是随宿主分发的程序。

## 保障与实现锚点

- contracts/replication.ts：版本、发送请求及存储/传输端口；core/operations/authority-service.ts：权威校验、比较、幂等及领域状态门禁。
- core/replication/engine.ts：顺序上传、原请求接续、拉取、冲突保留与解决协调。
- adapters/sqlite/replication-database.ts：权威事实与回执、确认副本、游标、编辑保护的一致提交；database.ts：普通写入的冲突和不确定门禁。
- apps/server/composition/workspace-sync.ts：内置/声明式处理器组装；transport/server.ts：所有者认证、身份绑定、限量请求与同步协议。未加入 MCP 授权或工具调用。
- desktop/host/sync-features.ts、renderer/sync-status.tsx：单一调度、状态及刷新；conflict-panel.tsx 同时支持待办与声明式领域的选择。
- tests/integration/replication.test.ts：真实 HTTP、磁盘、顺序/重复/失去回执、字段合并、删除恢复、分页事务失败、错误身份、离线重启及自定义领域隔离。tests/e2e/replication.test.mjs：两个实际桌面客户端及恢复路径。截图为 .build/replication-workspace.png。

保存成功的已确认历史与请求回执当前不清理；后续导出/恢复必须包含这些一致接续材料，不能只导出普通列表投影。
