## 原任务修改与重试

承接待办内容修改、待办截止日期设置，Architecture 为共享核心 operations、独立 todo-list 及桌面入口。领域包只解释合法字段变化，核心负责原操作核对和提交，不给调用方任意覆盖整条任务的接口。

每次请求冻结任务身份、原本机序号、操作身份及字段动作。核心从同任务不可变操作快照重建原版本，首次受理要求当前任务仍存在且序号相符，再通过 SQLite 预期序号和领域启用门禁提交。并发修改或删除拒绝，不把编辑转换成新增。

重复请求从同一不可变依据重建同一结果，由既有操作回执核对；较新任务不会被旧重试覆盖。当前操作快照与回执保存在既有 pending_operations，暂不提供清理；未来同步归档不能在仍有未核对请求时丢弃其依据。此处不新增独立文件作为业务事实源。

已知失败允许修改输入或沿原请求重试；未知结果锁住同任务其他写操作，保留原请求身份。明确放弃或取消不能抹去正在提交或尚未核对的请求。其他任务仍能受理。宿主队列串行协调领域请求，避免界面读取与其他任务保存互相误报失败。

## 字段行为

改文字只替换原文，非空原则与快速录入一致；改日期只替换或删除 dueDate，使用既有严格本地日历日期校验，不增加提醒或时刻。取消不写入。已完成任务也可编辑，创建时间与有效完成时间不因改字或改日期改变。

完成和恢复共用同一个领域动作；完成写本次时间，恢复移除当前有效完成时间，再完成重新计时。重复原请求不翻转状态；已经为目标状态的新请求不会刷新完成时间。呈现复用回看投影，成功前保留原勾选状态并显示处理中。

删除只生成原任务删除标记，不建立回收站或普通恢复入口。确认面板绑定具体任务的原版本并显示摘要及无撤销提示；并发更改后旧确认不能删除新版本。成功才关闭详情并移出回看；已被其他操作删除时提示不存在，绝不转为新增。

## 界面和请求生命周期

renderer/use-todo-progress.ts 按任务保存原请求与状态，在 React 更新前同步锁住同任务写入口。已知失败解锁并保留编辑；未知结果禁止反向操作或另建请求，只允许同 ID 核对重试。未知期间可以返回列表，原请求仍由同一工作空间界面托管；其他任务可继续处理，重开原详情恢复其冻结输入。正常关闭应用、停用等共享草稿保护同样检查详情草稿与未核对请求。未提交草稿的崩溃恢复仍不在当前范围。

详情里的文字与日期编辑分别保存、取消，不顺带保存另一个输入。正在提交时同任务编辑、取消和刷新暂停；取消或关闭未提交编辑保持原任务。后台刷新不更换正在编辑或确认删除的版本依据。结果未知不能通过丢弃草稿抹去；保存成功的旧回执也不能重新覆盖之后的新成果。

主进程只接受字段动作，不接受完整任意任务载荷；空间与领域固定在宿主可信绑定。先查原回执，已有回执可核对而不受后来的停用阻止；新写入须再次取得核心领域存储能力并在最终事务检查领域版本。列表与详情使用同一返回记录集；后续读取失败不把已确认写入改称失败。
